# Monitoring 화면 구성

## Lily와의 연결

참고 프로젝트: `/Users/hgsim/orca/lily-frontend`.
검정 배경 `#000000`, 따뜻한 흰색 `#f2f0ec`, 핑크 `#e0567e`, IBM Plex Sans KR 400/600을 맞췄다.
lily-frontend의 실행 화면에서 시연 배포 완료 상태를 확인했다. 원본 public/flower-mask.png와 particles.ts의 샘플링·깊이·색상 규칙을 사용해 46,386개의 입자로 같은 비대칭 백합을 만든다. 개화 완료 상태의 셰이더 표현을 적용해 흰 꽃잎 끝, 분홍색 중심과 노란 꽃가루를 맞췄다. 대시보드에서는 꽃을 1.45배로 키워 배치한다.

데스크톱 공간 보기에서 꽃의 관측점 다섯 개가 앱 지표, 버전 비교, 서버, 로그, 추이 패널에 연결된다. 관측점은 원본 꽃의 중심 입자에 부착한 탐색 UI이며 실제 서버 토폴로지를 나타내지 않는다.

꽃·2,400개의 별·연결선은 WebGLRenderer로, HTML 패널은 CSS3DRenderer로 렌더링한다. 두 렌더러는 같은 Three.js Scene과 PerspectiveCamera를 공유한다. 바닥이나 방의 외곽은 만들지 않고, 여러 깊이의 별과 희미한 성운 배경으로 우주 공간을 표현한다. 공간 보기는 화면 전체를 채우며 상태 안내·앱 선택·조회 기간·보기 전환은 화면 위에 고정한다. 패널에는 실제 XYZ 좌표가 있고, 카메라 회전에 따라 전체 패널 배치를 함께 회전시킨다. 각 패널의 quaternion은 카메라와 동일하게 맞춰 항상 정면을 향한다. 줌할 때 거리 비율로 패널 위치와 크기도 함께 조정해 화면의 배치와 가독성을 유지한다. 꽃과 별은 공간에 남으므로 주변을 360도로 둘러볼 수 있다. 연결선은 이동한 패널 가장자리를 매 프레임 추적하되 기존 버퍼를 재사용한다. React 포털로 CSS3D 객체 안에 기존 그래프와 로그를 렌더링해 필터와 검색을 유지한다. 관측점 버튼은 꽃의 3D 좌표를 화면에 투영해 마우스와 키보드로 선택할 수 있다.

입자 클릭 시 카메라가 연결된 패널의 정면으로 다가간다. 패널은 상세 크기로 펼쳐지고 다른 패널은 흐려지며 키보드 탐색에서 제외된다. 전체 공간 보기 / Esc로 사용자가 회전해 둔 직전 시점에 복귀하고, 시점 초기화로 첫 구도를 복원한다. 창 크기에 따라 전체 구도를 담는 카메라 거리를 조절한다.

현재 카메라 이동은 대시보드 공간 내부 연출이다. 배포 완료 화면에서 이어지는 카메라 전환은 아직 연결하지 않았다. 다음 단계에서는 lily-frontend의 LandingPage `onComplete`와 FlowerScene의 카메라 목표값을 연결하고, 카메라가 꽃 중심에 도달한 후 대시보드로 이동시키면 된다. 별도 페이지 이동 시 WebGL 캔버스는 연속되지 않으므로, 완전히 연속적인 전환에는 같은 앱 셸 안에서 씬을 공유하는 구성이 적합하다.

## 참고한 서비스

- [Three.js OrbitControls](https://threejs.org/docs/pages/OrbitControls.html): 수평 회전 제한 해제와 수직 0–π 범위, 회전·이동·줌 조작.
- [Grafana dashboard best practices](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/best-practices/): 큰 상태에서 상세로 내려가는 정보 계층, 단위와 그래프 설명, 과한 갱신 회피.
- [Datadog deployment tracking](https://www.datadoghq.com/blog/datadog-deployment-tracking/): 버전별 요청·에러·응답 시간 비교, 배포 문제와 관련 정보 연결.

브랜드와 공간 표현은 Lily에 맞추고, 모니터링 정보 구조와 비교 방식만 참고했다.

## 직관성 개선

| 기존 문제 | 변경 |
|---|---|
| 큰 경고 영역과 반복되는 정상 배지가 화면을 지배 | 짧은 상태 안내, 문제에만 강한 색상, 로그로 이동하는 실제 버튼 |
| 모바일에서 지표 한 장이 큰 높이를 차지 | 2열 요약, 네 가지 수치를 첫 화면에서 확인 |
| 요약 5분과 그래프 15분/1시간의 범위 혼동 | 요약과 추이의 집계 범위를 각각 표시 |
| 서버 CPU·메모리와 상태 판단 기준이 중복 | 게이지는 수량, 상태 배지는 API의 판정 사용 |
| 최근 로그를 읽기만 가능 | 수준·버전 필터, 수집된 결과 내 검색, Pod·Trace ID·예외 펼치기 |
| 공간의 패널을 자세히 읽기 어려움 | 클릭하면 카메라가 패널 정면으로 이동하고 상세 크기로 펼침 |

## 사용과 한계

- 1100px 이상: 공간/목록 보기. 그 미만: 세로 패널 레이아웃, WebGL 생성하지 않음.
- 동작 줄이기 설정: 입자 움직임과 카메라 이동 보간을 중단. 수동 회전·줌은 계속 사용할 수 있으며 상세 화면으로 즉시 이동한다.
- WebGL 실패: 패널과 일반 제어는 계속 동작.
- 로그 검색과 버전 필터는 최신 수집 결과 범위에 적용. 전체 로그 저장소 검색이 아니다.
- 오류 로그 바로가기는 오류율 문제가 있으면 해당 버전 ERROR, 그 외 성능 문제는 WARN 이상으로 시작한다. 실제 지연과 로그를 정확히 연결하려면 백엔드의 request duration/trace 데이터가 필요하다.
- 공간 보기의 작은 그래프는 개요용이다. 상세 보기와 목록 보기에는 더 높은 그래프와 추가 설명을 표시한다.
- CSS3D 패널은 DOM 레이어로 렌더링하므로 WebGL 꽃잎과 깊이 버퍼를 공유하지 않는다. 패널과 꽃의 배치가 겹치지 않게 설계했지만 수동 시점에 따라 일부 겹쳐 보일 수 있다.
- 실제 API와 k3s 클러스터는 아직 연결하지 않았다.

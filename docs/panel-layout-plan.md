# 공간 보기 패널 배치 점검과 수정안

작성일: 2026-10-03. 측정과 제안까지 했고, 배치 변경은 **아직 코드에 적용하지 않았습니다**(실험은 되돌림).

## 1. 문제

공간 보기의 패널 여섯 개는 3D 좌표(`PANEL_PLACES`)에 고정돼 있고, 화면에 보이는 크기는 내용에 따라 달라집니다.
빈 상태에서는 겹치지 않지만 **내용이 다 차면 서로 가립니다.** 패널 내용은 `.bubbleContent`가 `max-height: 390px`까지 자랍니다.

## 2. 측정 방법

- 로컬 대시보드를 iframe으로 열고 `/monitor`, `/control` 응답을 **가장 많이 찬 내용**으로 바꿔 끼웠습니다.
  - 파드 6개(재시작·장애 포함), 로그 100줄(긴 예외 문장), 배포 슬롯 2개, DB 2개, 지표 시계열 30점, 상태 경고 문구
  - 거점과 트래픽은 에이전트가 연결된 온프레미스 프로젝트 상태(버스팅 켜짐)
- 화면 크기별로 여섯 패널의 실제 사각형(`getBoundingClientRect`)을 구해 패널끼리, 고정 UI(상태 문구, 조작 방법 메뉴, 오른쪽 위 버튼, 보기 전환, 왼쪽 아래 이름)와 겹치는 크기를 계산했습니다.
- 측정 크기: 1920×1080, 1654×952, 1440×900, 1280×720.

## 3. 현재 배치의 측정 결과

내용을 가득 채웠을 때 패널 높이(1654×952 기준, px): 01 앱 지표 366 · 02 배포 412 · 03 파드 427 · 04 로그 277 · 05 추이 239 · 06 거점 239

| 겹침 | 크기 (가로×세로 px) | 가려지는 것 |
|---|---|---|
| 01 앱 지표 × 03 파드 | 366×85 | 03 제목과 첫 파드 |
| 03 파드 × 06 거점과 트래픽 | 268×107 | 03 아래쪽 파드 목록 |
| 02 배포 × 04 로그 | 302×67 | 04 제목과 필터 |
| 04 로그 × 05 추이 | 253×8 | 05 제목 위쪽 |
| 상태 문구 × 01·02 | 19×18, 17×34 | 01·02의 모서리와 `상세 ↗` |

1920×1080과 1440×900에서도 같은 네 곳이 같은 비율로 겹쳤습니다. 화면 크기를 바꿔도 해결되지 않는 **구조적 문제**입니다.

**원인:** 왼쪽 세로 합이 366+427+239 = 1032px, 오른쪽이 412+277+239 = 928px인데, 화면에서 쓸 수 있는 높이는 약 870px(위쪽 고정 UI와 아래 여백 제외)입니다. 한 열에 세 개를 쌓을 수 없습니다.

## 4. 수정안 (1단계: 측정으로 확인함)

두 가지를 같이 바꿉니다. 하나만 바꾸면 해결되지 않습니다.

### 4.1 개요 패널의 내용 높이 제한을 줄임

`components/dashboard.module.css` 파일 끝에 추가합니다. 긴 목록은 패널 안에서 스크롤하고, 전체 내용은 `상세 ↗`에서 봅니다. 앱 지표는 타일 4개라 제한을 두지 않습니다.

```css
@media (min-width: 1100px) {
  .spatial .scenePanel:not([data-selected='true']) .bubbleContent { max-height: 230px; }
  .spatial .scenePanel[data-panel='metrics']:not([data-selected='true']) .bubbleContent { max-height: none; }
}
```

효과(1654×952): 02 배포 412→272, 03 파드 427→277.

### 4.2 패널 위치를 다시 잡음

`components/ParticleStage.tsx`의 `PANEL_PLACES`:

| 패널 | 지금 | 제안 | 이동 의도 |
|---|---|---|---|

| compare | `[3.5505, 1.7524, -.0738]` | `[3.87, 2.24, -.0738]` | 위로, 상태 문구에서 오른쪽으로 |
| servers | `[-3.7213, -1.4524, 1.2127]` | `[-5.12, -1.83, 1.2127]` | 왼쪽으로 빼서 06과 가로로 분리 |

### 측정 결과

| 화면 | 패널끼리 겹침 | 고정 UI와 겹침 | 화면 밖으로 잘림 |
|---|---|---|---|
| 1654×952 | **0** | **0** | 없음 |
| 1440×900 | **0** | 조작 방법 메뉴×01 (21×150), 02×오른쪽 위 버튼 (19×13) | 없음 |

1920×1080은 측정하지 않았습니다(배치가 화면에 비례해 커지므로 1654와 같을 것으로 봅니다).

## 5. 남은 문제와 제안 (2단계: 확인 전)

작은 화면에서는 패널은 화면 크기에 비례해 줄어드는데 고정 UI는 그대로라서 모서리가 겹칩니다.

| 문제 | 제안 |
|---|---|
| 조작 방법 메뉴가 01을 가림 (1440) | 접었을 때는 폭을 줄이고(`fit-content`), 펼쳐 둔 채 시작하는 기준을 1400px에서 1500px로 올림 |
| 02가 오른쪽 위 버튼과 겹침 (1440) | `패널 배치 초기화`·`시점 초기화`를 조작 방법 메뉴 안으로 옮김. 오른쪽 위가 비고 메뉴가 한곳에 모임 |
| 상태 문구가 01·02 모서리를 가림 (1280) | 상태 문구의 최대 폭을 440→340px로 줄이거나, 위치를 조작 방법 메뉴 위로 옮김 (정해 주세요) |

## 6. 한계

- 위치는 3D 좌표라서 **화면 크기별로 정확히 맞추려면 한계**가 있습니다. 근본적으로는 실제 화면 크기와 고정 UI 영역을 보고 패널 위치를 계산하는 배치 함수가 필요합니다. 이번 제안은 그 전까지의 정적 값입니다.
- 사용자가 패널을 직접 끌어 옮긴 배치는 바뀌지 않습니다(`패널 배치 초기화`를 눌러야 새 기본값 적용).
- 확대한 상세 보기(패널 하나를 크게 보는 화면)는 따로 동작하므로 이번 점검 범위가 아닙니다.
- 자동화 브라우저가 백그라운드 탭이라 렌더링이 멈춰서, 화면을 한 번씩 캡처해 그리게 한 뒤 측정했습니다.
